# ENKU release & openness policy

Status: **project policy baseline / October 2026**

ENKU is **open, repairable and local-first**, but active product development is not required to publish every production-ready file in real time.

## Principle

> **Open what improves ownership. Delay what only improves copying.**

For ENKU, openness means that owners should be able to understand, repair, integrate and keep using the device without depending on an ENKU cloud service.

## Public during active development

Public by default:
- product goals and user-facing behavior;
- firmware architecture and stable interfaces where useful;
- repairability requirements;
- compatibility and local-first behavior;
- selected development updates;
- contribution areas that can be supported safely.

Private by default until an appropriate release gate:
- production PCB layout and manufacturing packages;
- Gerbers, pick-and-place and factory-ready BOM;
- supplier pricing and sourcing strategy;
- factory test/calibration tooling;
- reproduction-ready enclosure CAD;
- unreleased product variants;
- private market/economic research;
- unstable internal engineering experiments.

## At product launch / shipping

Owners should receive:
- complete user documentation;
- recovery/update instructions;
- repair/disassembly guidance where safe;
- battery/service information;
- documented ports and supported local interfaces;
- known limitations.

## After stable production

ENKU may release:
- firmware source and SDKs;
- protocol/interface specifications;
- selected schematics;
- service/printable mechanical files;
- pinouts and expansion information;
- selected hardware design material.

Exact scope and timing are product-specific.

## Existing public history

ENKU began as a public open-source project, so earlier repository history already contains engineering material. That history is not rewritten or misrepresented.

The policy applies to **what is published from this point forward**, especially production-ready manufacturing data.

## AI-assisted development

Development tools are not part of ENKU's product positioning.

AI-assisted tools may be used for research, engineering assistance, code review, documentation, concept exploration and workflow automation alongside conventional engineering, review and physical validation.

Public authorship remains **ENKU**.

If asked directly, the accurate description is:

> AI-assisted tools are used alongside conventional engineering, design, review and testing workflows.

No generated output substitutes for electrical review, DRC/ERC, firmware tests, manufacturing validation or physical product decisions.
