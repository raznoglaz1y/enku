PROJECT STATUS · OCT 2026

Building the real reader.

ENKU has moved beyond product definition and reference-board-only planning. The reader software is becoming memory-aware and device-oriented, while a portrait-first custom ENKU mainboard is now being specified in parallel with the Waveshare bring-up path.

HARDWARE TRACKS

NEXT PROOF POINT

NOW

What is actually happening.

No percentage bars. These are concrete project states derived from the repository: what is established, what is being integrated now, and what still depends on the physical hardware.

DONE

Product & UI foundation

Open-source scope, physical-control interaction model, e-paper UI principles, typography presets, localization architecture and the core Figma design system are defined.

DONE

Reader core foundation

TXT, EPUB and FB2 now share the concrete Book Loader path. EPUB/FB2 parsing uses bounded or ranged reads, semantic positions survive relayout and section transitions, and stale checkpoints recover safely instead of breaking book open.

DONE

Reader persistence hardening

Checkpoint restore, invalid-section fallback, edge navigation and relayout stability are regression-tested. Back, Sleep and Power Off now share one controlled reader-state flush path instead of duplicating persistence logic.

DONE

E-paper refresh policy

Region/full refresh escalation now includes anti-ghosting accounting. After five fast or partial updates ENKU forces a clean full refresh before continuing incremental updates.

DONE

Board capability profiles

The firmware now distinguishes board capabilities from board wiring. Waveshare is marked as ReferenceHardware while ENKU R0.1 Base / Pro / Pro Wireless remain explicit DesignTarget profiles until physical validation.

DONE

Bootstrap resilience

microSD mount/setup failures get dedicated recovery guidance and automatic retry. Noto Sans Regular is firmware-owned with visible fallback behavior, and board-profile mismatches or unrecoverable boot-state failures now render built-in recovery screens instead of disappearing into serial-only errors.

DONE

Runtime failure recovery

Renderer/refresh failures are now distinct from one-off action failures. Three consecutive runtime failures trigger a built-in APP FAIL recovery screen, while successful cycles reset the streak. Input initialization and initial Library render failures also get visible recovery states.

DONE

Degraded optional services

Wi-Fi and PMU telemetry are no longer boot-critical dependencies. ENKU keeps Library and Reading available when those optional services fail, while Sleep/Power Off report their real availability instead of pretending an action succeeded.

DONE

ESP-IDF platform baseline

Storage, SSD1677 display paths, refresh service integration, physical input/power coordination, Wi-Fi policy and persistent application runtime work now exist in the device target and compile in CI.

NOW

Custom mainboard R0.1

A portrait-first ESP32-S3 mainboard is now an active engineering track with Base / Cover / Pro / Pro Wireless variants, Dock pogo charging, BMI270, Hall sensing, power-path architecture and an SSD1677 raw-panel integration baseline.

NOW

Close schematic blockers

The remaining work before a real PCB schematic freeze is current-panel FPC verification, Good Display high-voltage reference values, exact EPD power parts, microSD connector mechanics and Pro frontlight/Qi validation.

NOW

Canonical EN screens

The English UI review boards still need to be finished and stress-tested with longer localized strings before they become the final implementation baseline.

NEXT

Physical hardware validation

Board revision, controls, microSD, display orientation, full/fast/partial refresh, ghosting, charging and real power consumption must be measured on the delivered Waveshare hardware.

NEXT

First usable offline MVP

The remaining MVP work is increasingly hardware-facing: real-device bring-up, board-profile validation, low-power measurements and final refresh tuning must converge around the already working offline reader stack.
